Each <candidate> carries a `key`, the first reader's finding, the Spanish
<excerpt> it quotes, the <spanish_context> around it, and — only where the first
reader said the original was needed — an <english_context> holding the source
sentences for that same stretch.

**The first reader could not see the English.** That is deliberate: it read the
Spanish as Spanish. Where <english_context> is present, you can now settle
questions it could only nominate. Where it is absent, judge the finding on the
Spanish alone, exactly as the first reader did — do not retract something merely
because you cannot see the original.

Where <english_context> is present, remember it is a *neighbourhood*, aligned
sentence by sentence. The sentence corresponding to the excerpt is in there, but
so are its neighbours; do not treat a detail from an adjacent sentence as proof
that the excerpt is wrong.

For each candidate return exactly one verdict:

- **CONFIRM** — a real defect, correctly described, worth an editor's time. Keep
  it as it stands, or supply a better minimal `suggestion`.
- **RETRACT** — not a defect, or not one worth reporting. Use this freely. The
  most common reasons are: the Spanish is idiomatic after all; the construction
  is valid though unusual; the "error" is a legitimate regional or period form;
  the English shows the odd wording is faithful to an odd original; the reader
  was applying a preference rather than a rule. A retraction is a *success* of
  this pass, not a failure of it.
- **RECLASSIFY** — a real defect, but the first reader got something wrong about
  it: the wrong `category`, an overstated or understated `severity`, or a
  `message` that misdiagnoses the cause. Supply the corrected fields.

Judge each candidate independently. Do not let the number of candidates
influence you: confirming all of them and retracting all of them are both
legitimate outcomes.

Be strict about `severity`:

- "error": meaning is wrong or lost, or a hard rule is plainly broken.
- "warning": clearly worth correcting; the meaning still survives.
- "info": a genuine localized defect of small consequence.

If a candidate only rises to "an editor might phrase this differently", it is a
RETRACT, not an "info".

Respond with ONLY a JSON object, no other text, in exactly this shape:

{
  "verdicts": {
    "<candidate key>": {
      "verdict": "CONFIRM" | "RETRACT" | "RECLASSIFY",
      "reason": "<one sentence: why, naming the evidence you used>",
      "used_source": true | false,
      "category": "<only for RECLASSIFY: the corrected category>",
      "severity": "<only for RECLASSIFY: the corrected severity>",
      "message": "<only for RECLASSIFY: the corrected one-sentence description>",
      "suggestion": "<optional: a better minimal fix, for CONFIRM or RECLASSIFY>"
    }
  }
}

Every `key` present in <candidates> MUST appear exactly once in `verdicts`, and
`verdicts` must contain no other keys. Set `used_source` to true only if an
<english_context> was present for that candidate AND it actually changed or
corroborated your judgment.

Any `suggestion` you supply must be a **drop-in replacement for that candidate's
<excerpt> alone** — nothing but book text, no commentary, no ellipsis, no words
that already appear before or after the excerpt, and every raya you open closed.
If you have no concrete replacement to offer, omit the field and leave the first
reader's suggestion standing.
